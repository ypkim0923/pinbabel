# AnalysisRun과 Embabel Flight Recorder 요구사항

## Summary

모든 CLI 분석 요청에 실행 식별자를 부여하고, 분석 상태와 Embabel 실행 이벤트를 안전하게 추적한다. 사용자는 최근 실행 목록과 개별 실행의 최종 보고서 및 시간순 추적 정보를 CLI에서 조회할 수 있다.

---

## Problem Frame

현재 fixture 기반 분석은 CLI에서 최종 결과를 반환하지만, 어떤 계획과 Action을 거쳐 결과가 생성되었는지 실행 후 확인하기 어렵다. 실패하거나 예상과 다른 결과가 나와도 계획 변경, Tool 호출, LLM 처리시간과 실패 지점을 하나의 실행 단위로 연결할 수 없다.

이 상태에서는 prompt와 모델을 변경했을 때 동작을 비교하기 어렵고, 이후 REST·A2A·A2UI가 공통으로 사용할 실행 수명주기와 correlation 기준도 없다. 한편 SNS 원문과 LLM 메시지를 무분별하게 저장하면 개인정보와 prompt 정보가 실행 이력에 남는 위험이 있다.

---

## Actors

- A1. CLI 사용자: 분석을 요청하고 실행 식별자, 결과와 추적 정보를 확인한다.
- A2. Pinbabel 분석 애플리케이션: 요청을 검증하고 Embabel 분석 실행과 실행 상태를 조정한다.
- A3. Embabel Agent 실행기: 계획, 재계획, Action, Tool, LLM과 종료 이벤트를 발생시킨다.
- A4. 실행 기록 저장소: 실행 상태, 안전한 이벤트 metadata와 최종 보고서를 보관하고 조회한다.

---

## Key Flows

- F1. 정상 분석 실행
  - **Trigger:** A1이 유효한 주식 인플루언서 분석 요청을 제출한다.
  - **Actors:** A1, A2, A3, A4
  - **Steps:** A2가 실행 식별자를 생성하고 실행을 시작한 뒤, A3가 발생시키는 이벤트를 A4에 시간순으로 기록한다. 분석이 끝나면 A2가 최종 보고서와 종료 상태를 기록하고 실행 식별자를 포함한 결과를 반환한다.
  - **Outcome:** 사용자는 완료된 보고서를 받고 동일한 실행 식별자로 실행 이력을 조회할 수 있다.
  - **Covered by:** R1, R2, R3, R5, R8, R10

- F2. 거절된 요청
  - **Trigger:** A1이 빈 입력, 허용 길이 초과 또는 업무 범위 밖 요청을 제출한다.
  - **Actors:** A1, A2, A4
  - **Steps:** A2가 실행 식별자를 생성하고 검증 결과를 기록한다. Embabel 분석은 시작하지 않으며 입력 원문 없이 거절 코드와 사유만 저장한다.
  - **Outcome:** 사용자는 거절 결과와 실행 식별자를 받고 해당 실행을 조회할 수 있다.
  - **Covered by:** R1, R4, R6, R8

- F3. 기록 저장 실패가 발생한 분석
  - **Trigger:** 실행 생성 또는 이벤트·보고서 기록 중 A4를 사용할 수 없다.
  - **Actors:** A1, A2, A3, A4
  - **Steps:** A2는 기록 실패를 분석 실행과 격리하고 가능한 경우 분석을 계속한다. 결과에 추적 정보 사용 불가 경고를 포함하되 저장 실패 때문에 분석 결과를 실패로 바꾸지 않는다.
  - **Outcome:** 사용자는 실행 식별자와 분석 결과 또는 본래의 분석 실패를 받으며, 추적 정보가 불완전함을 알 수 있다.
  - **Covered by:** R1, R7, R8, R9

---

## Requirements

**실행 식별과 수명주기**

- R1. 모든 분석 요청은 검증이나 저장 성공 여부와 무관하게 애플리케이션에서 고유한 `runId`를 먼저 부여받아야 한다.
- R2. 유효한 분석 실행은 생성, 실행 중, 완료 또는 실패 상태 전이를 추적해야 하며 각 상태의 발생 시각을 확인할 수 있어야 한다.
- R3. 완료 실행은 최종 분석 보고서와 총 처리시간을 제공하고, 실패 실행은 민감정보가 제거된 실패 분류와 요약을 제공해야 한다.
- R4. 빈 입력, 길이 제한 초과와 업무 범위 밖 요청은 분석 결과의 거절 여부와 별도로 실행 상태 `REJECTED`로 기록하며 Embabel 분석을 시작하지 않아야 한다.

| 실행 상태 | 의미 | 종료 상태 |
|---|---|---|
| `CREATED` | 실행 식별자가 생성되고 분석 시작 전인 상태 | 아니요 |
| `RUNNING` | Embabel 분석이 시작된 상태 | 아니요 |
| `COMPLETED` | 최종 분석 보고서가 생성된 상태 | 예 |
| `FAILED` | 분석 자체가 완료되지 못한 상태 | 예 |
| `REJECTED` | 입력 검증 또는 업무 범위 정책으로 실행하지 않은 상태 | 예 |

**Embabel 실행 추적**

- R5. 실행 추적은 Embabel이 공식적으로 제공하는 실행 이벤트 경계를 사용하여 계획 수립, 재계획, Action 시작·종료, Tool 호출, LLM 호출과 실행 종료를 동일한 `runId` 아래 시간순으로 연결해야 한다.
- R6. 실행 이벤트에는 허용된 metadata만 저장해야 한다. 최소 범위는 이벤트 종류, 발생 시각, Action·Tool·모델 식별정보, 처리시간, 성공 여부와 제공 가능한 token·비용 지표다.
- R7. LLM prompt·응답 원문, Tool 입력·출력 원문, API key와 credential은 실행 이벤트나 오류 기록에 저장하거나 표시하지 않아야 한다.
- R8. 각 분석 결과는 `runId`와 `traceAvailable` 여부를 포함하고, 추적 정보가 완전하지 않으면 사용자가 식별할 수 있는 경고를 제공해야 한다.
- R9. 실행 기록기의 오류는 Embabel listener 또는 저장소 경계를 넘어 분석 실행을 중단시키지 않아야 하며, 원래 분석의 성공·실패 의미를 변경하지 않아야 한다.

**최종 산출물과 CLI 조회**

- R10. 완료 실행은 종목별 sentiment, confidence, 판단 사유, 근거 post ID·URL과 필요한 최소 인용문을 포함한 최종 구조화 보고서를 보관해야 한다.
- R11. 기존 분석 CLI 결과에는 `runId`와 추적 가능 여부가 표시되어야 한다.
- R12. 사용자는 별도의 CLI 명령으로 최신 순 최근 실행 20건의 `runId`, 상태, 시작 시각과 처리시간 요약을 조회할 수 있어야 한다.
- R13. 사용자는 `runId`로 하나의 실행을 조회하여 상태, 처리시간, 결과 또는 거절·실패 요약, 경고와 시간순 이벤트를 확인할 수 있어야 한다.
- R14. 존재하지 않는 `runId` 조회는 다른 실행 정보나 내부 오류를 노출하지 않고 찾을 수 없음을 명확하게 알려야 한다.

**저장 범위와 보존**

- R15. 최초 버전의 실행 기록은 애플리케이션 프로세스가 살아 있는 동안만 유지되며 애플리케이션 재시작 후 보존을 보장하지 않는다.
- R16. 실행 기록 저장 방식은 분석 Domain과 Embabel Action이 특정 데이터베이스 기술에 직접 의존하지 않도록 경계가 분리되어야 한다.

## Acceptance Examples

- AE1. **Covers R1, R2, R5, R8, R10, R11.** Given 유효한 fixture 분석 요청, when 분석이 성공하면, CLI 결과에 `runId`와 `traceAvailable: true`가 표시되고 실행 상세에는 `CREATED`, `RUNNING`, `COMPLETED` 수명주기와 Embabel 이벤트 및 최종 보고서가 연결되어 있다.
- AE2. **Covers R1, R4, R6, R7.** Given 주식 인플루언서 분석과 무관한 요청, when CLI가 요청을 처리하면, `runId`와 거절 결과를 반환하고 실행은 `REJECTED`로 조회되며 입력 원문과 Embabel 이벤트는 저장되지 않는다.
- AE3. **Covers R3, R5, R7, R8.** Given Embabel 실행 중 LLM 호출이 실패한 요청, when 실행이 종료되면, 실행은 `FAILED`로 조회되고 실패한 이벤트와 처리시간은 보이지만 prompt, 응답 원문과 credential은 보이지 않는다.
- AE4. **Covers R7, R8, R9.** Given 이벤트 기록 중 저장소 오류가 발생하지만 분석 자체는 성공한 요청, when 결과가 반환되면, 분석 보고서는 유지되고 `traceAvailable: false`와 경고가 표시된다.
- AE5. **Covers R12, R13.** Given 20건을 초과하는 실행 이력, when 최근 실행 목록을 조회하면, 최신 20건만 표시되며 각 `runId`로 상세 상태와 시간순 이벤트를 조회할 수 있다.
- AE6. **Covers R14.** Given 존재하지 않는 `runId`, when 실행 상세를 조회하면, 찾을 수 없다는 결과만 표시되고 다른 실행의 정보는 노출되지 않는다.
- AE7. **Covers R15.** Given 실행 이력이 존재하는 상태, when 애플리케이션을 재시작하면, 이전 프로세스의 실행 이력은 조회되지 않아도 요구사항 위반으로 간주하지 않는다.

## Success Criteria

- CLI 사용자가 모든 분석 결과와 거절 결과에서 실행 식별자를 확인하고, 애플리케이션이 실행 중인 동안 해당 실행의 상태와 추적 정보를 다시 조회할 수 있다.
- 정상, 거절, 분석 실패와 기록 실패 시나리오가 자동 테스트로 구분되어 검증된다.
- 저장된 이벤트와 로그를 검사했을 때 LLM·Tool 원문, API key와 credential이 포함되지 않는다.
- 하나의 실행에서 계획, 재계획, Action, Tool, LLM과 종료 이벤트가 발생 순서와 처리시간을 보존한다.
- 이후 REST, A2A, A2UI Adapter가 실행 식별자와 조회 유스케이스를 중복 구현 없이 사용할 수 있도록 요구사항 경계가 명확하다.

---

## Scope Boundaries

- 비동기 제출, background 실행, 취소, 일시정지와 재개는 이번 범위에 포함하지 않는다.
- REST, A2A와 A2UI Adapter 및 프로토콜별 contract test는 후속 단계로 미룬다.
- 애플리케이션 재시작 이후의 실행 이력 보존과 운영용 외부 데이터베이스는 포함하지 않는다.
- LLM prompt·응답 및 Tool 입력·출력 원문을 보관하거나 다시 재생하는 기능은 포함하지 않는다.
- SNS 실데이터 Adapter, golden dataset 평가, Human-in-the-loop와 MCP 연동은 포함하지 않는다.
- token 또는 비용 정보가 현재 provider와 Embabel 이벤트에서 제공되지 않으면 값을 추정하지 않는다.

---

## Key Decisions

- 동기 실행을 유지한다: 현재 CLI 사용 흐름을 보존하고 비동기 수명주기는 API 단계에서 설계한다.
- 모든 요청에 실행 식별자를 부여한다: 성공 실행뿐 아니라 거절과 추적 실패도 일관되게 상관관계를 가질 수 있다.
- 이벤트는 허용 목록 metadata만 기록한다: 관측 가능성을 확보하면서 SNS 원문과 LLM 메시지의 불필요한 보관을 막는다.
- 최종 보고서는 저장한다: 실행 상세 조회와 분석 결론의 provenance를 제공한다.
- 기록 실패는 분석 실패와 분리한다: 관측 기능의 장애가 분석 결과의 의미를 바꾸지 않게 한다.
- 최초 저장 수명은 프로세스 단위다: 현재 단계에서는 H2 Embedded 인메모리 저장 정책을 따른다.

---

## Dependencies / Assumptions

- 현재 프로젝트의 Embabel 1.5.0이 실행별 listener와 계획, 재계획, Action, Tool, LLM 및 종료 이벤트를 제공한다.
- 저장이 필요한 최초 구현에는 프로젝트의 H2 Embedded 인메모리 DB를 사용한다.
- 데이터베이스 변경은 프로젝트 지침에 따라 Liquibase로 관리한다.
- provider가 token 또는 비용을 제공하지 않는 실행에서도 나머지 추적 기능은 정상 동작해야 한다.
- 최종 보고서의 최소 인용문과 URL은 사용자가 명시적으로 저장하기로 선택한 분석 산출물이며, 이벤트 원문 저장 금지와 구분한다.

## Outstanding Questions

### Deferred to Planning

- [Affects R5, R6][Needs research] Embabel 1.5.0의 각 이벤트에서 원문 접근 없이 안정적으로 추출할 수 있는 token, 비용, 모델과 처리시간 metadata를 확정한다.
- [Affects R9, R16][Technical] 기록 실패 격리를 유지하면서 상태와 이벤트 순서를 일관되게 저장할 transaction 경계를 확정한다.
