# Thymeleaf 주식 인플루언서 분석 화면 요구사항

## Summary

로그인 없이 주식 인플루언서 목록을 탐색하고, 프로필별 최근 포스트의 회사 언급과 감정 분석 결과를 확인하는 SSR 화면을 제공한다. Fake 인플루언서는 비용 없는 즉시 결과를, 실제 X 계정은 명시적으로 실행하는 비동기 분석을 제공한다.

---

## Problem Frame

Pinbabel은 Embabel Framework의 Agent, Tool, 비동기 실행과 결과 추적 기능을 학습하기 위한 프로젝트다. 현재 핵심 기능은 CLI와 protocol API로 실행할 수 있지만, 사용자가 인플루언서를 탐색하고 분석 결과와 근거를 한 흐름에서 확인할 수 있는 웹 화면은 없다.

운영 서비스로 확장하는 것이 목적이 아니므로 로그인과 개인화보다 핵심 도메인 흐름을 직접 확인하는 것이 중요하다. 실제 X 호출은 비용이 발생하므로 일반적인 화면 탐색이나 데모 과정에서 의도하지 않은 외부 호출이 일어나서는 안 된다.

---

## Actors

- A1. 실험 사용자: Pinbabel의 인플루언서 탐색과 Embabel 분석 결과를 브라우저에서 검증한다.
- A2. Pinbabel 분석 시스템: Fixture 또는 실제 X 포스트 분석을 실행하고 상태, 결과, 근거와 안전한 실패 정보를 제공한다.

---

## Key Flows

- F1. 인플루언서 목록 탐색
  - **Trigger:** A1이 첫 화면에서 주식 인플루언서 조회 버튼을 누른다.
  - **Actors:** A1, A2
  - **Steps:** 같은 화면 아래에 실제 계정 1명과 Fake 인플루언서 9명의 프로필 카드가 나타난다. A1은 카드에서 아바타, 표시 이름, X 핸들, 한 줄 소개와 계정 유형을 확인한다.
  - **Outcome:** A1이 분석할 인플루언서를 선택할 수 있다.
  - **Covered by:** R1, R2, R3

- F2. Fake 인플루언서 분석 확인
  - **Trigger:** A1이 Fake 인플루언서 프로필 카드를 선택한다.
  - **Actors:** A1, A2
  - **Steps:** 프로필 상세와 고정 포스트 10개의 분석 결과가 즉시 표시된다. A1은 네 가지 감정 영역에서 회사를 탐색하고 필요한 회사의 근거를 펼친다.
  - **Outcome:** 외부 API나 LLM 비용 없이 목록부터 분석 근거까지 전체 성공 흐름을 검증한다.
  - **Covered by:** R4, R6, R7, R8, R9

- F3. Serenity 실시간 분석
  - **Trigger:** A1이 Serenity 프로필에서 최근 10개 분석 버튼을 누른다.
  - **Actors:** A1, A2
  - **Steps:** 분석 작업이 접수되고 진행 상태가 자동 갱신된다. 완료되면 같은 분석 화면에 회사별 감정 결과와 근거가 표시된다.
  - **Outcome:** 사용자의 명시적 행동 한 번으로만 유료 외부 호출이 시작되고, 완료 여부를 별도 수동 새로고침 없이 확인한다.
  - **Covered by:** R5, R6, R7, R10, R11

- F4. 실시간 분석 실패 복구
  - **Trigger:** Serenity 분석이 credit 부족, rate limit, timeout 또는 provider 장애로 종료된다.
  - **Actors:** A1, A2
  - **Steps:** 화면은 비밀정보나 provider 원문 없이 안전한 원인과 가능한 다음 행동을 보여준다. 재시도가 허용되는 경우 A1이 다시 시도할 수 있다.
  - **Outcome:** 결과가 없는 이유와 복구 방법을 이해하며 무분별한 재실행을 피한다.
  - **Covered by:** R12, R13

## Requirements

**인플루언서 탐색**

- R1. 첫 화면은 로그인 없이 접근할 수 있고 주식 인플루언서 리스트 조회 버튼을 제공해야 한다.
- R2. 조회 버튼을 누르면 페이지 이동 없이 같은 화면 아래에 정확히 10명의 프로필 카드가 표시되어야 한다.
- R3. 목록은 실제 X 계정 Serenity(`@aleabitoreddit`) 1명과 서로 다른 투자 성향·섹터를 가진 Fake 인플루언서 9명으로 구성해야 한다. 각 카드는 프로젝트가 관리하는 아바타, 표시 이름, X 핸들, 한 줄 소개와 `실제 계정` 또는 `Fixture` 배지를 보여줘야 한다.
- R4. Fake 프로필을 선택하면 해당 인플루언서의 고정 포스트 10개를 기반으로 한 분석 결과를 외부 API와 LLM 호출 없이 즉시 보여줘야 한다.
- R5. Serenity 프로필을 선택하는 것만으로는 외부 호출을 시작하지 않아야 한다. 실시간 분석은 상세 화면의 명시적인 최근 10개 분석 버튼을 눌렀을 때만 시작해야 한다.

**분석 결과**

- R6. 분석 화면은 프로필 정보와 최근 포스트 분석 결과를 한 화면에서 확인할 수 있어야 한다.
- R7. 회사 결과는 `긍정`, `부정`, `중립`, `판단 불가` 네 영역으로 구분해야 하며, 결과가 없는 영역도 상태를 이해할 수 있게 표시해야 한다.
- R8. 각 회사 항목은 회사명, 언급 횟수와 분석 신뢰도를 기본 정보로 보여줘야 한다.
- R9. 회사 항목의 근거를 펼치면 관련 포스트 발췌문, 감정 판단 이유, 작성 시각과 원문 링크를 확인할 수 있어야 한다.
- R10. Serenity 분석이 실행 중이면 접수, 진행, 완료 또는 실패 상태가 자동으로 갱신되어야 하며, 전체 페이지 수동 새로고침을 요구하지 않아야 한다.
- R11. 결과 화면은 공개 SNS 발언에 대한 자동 분석이며 투자 자문이 아니라는 안내를 제공해야 한다.

**실험·실패 정보**

- R12. 분석 화면은 기본적으로 접힌 실험 정보 영역을 제공해야 한다. 펼치면 실행 ID, 현재 상태, 외부 호출 수, 실행 시간, cache 사용 여부와 경고를 확인할 수 있어야 한다.
- R13. 실시간 분석 실패 시 credential, provider 원문 또는 내부 예외를 노출하지 않고, 원인별 안전한 안내와 허용 가능한 다시 시도 행동을 제공해야 한다.
- R14. 인플루언서 목록 조회와 Fake 분석 탐색은 X API나 LLM 호출을 발생시키지 않아야 한다.

**시각적 경험**

- R15. 화면은 밝은 테마의 소셜 피드 스타일을 사용해야 한다. 프로필과 포스트 맥락을 중심에 두되 감정 결과는 구분 가능한 분석 패널로 표현하고, 긍정·부정 색상은 정보 판독을 해치지 않게 절제해야 한다.

## Acceptance Examples

- AE1. **Covers R1, R2, R3, R14.** 첫 화면에서 조회 버튼을 누르면 같은 화면에 Serenity 1명과 Fixture 9명의 카드가 나타나며 외부 호출은 발생하지 않는다.
- AE2. **Covers R4, R6, R7, R8, R9.** Fake 프로필을 선택하면 분석 화면으로 이동하고, 네 감정 영역의 회사 결과가 즉시 보이며 회사 근거를 펼쳐 포스트 발췌와 판단 이유를 확인할 수 있다.
- AE3. **Covers R5, R10, R12.** Serenity 프로필을 선택하면 아직 결과가 없는 상세 화면이 보이고 비용은 발생하지 않는다. 분석 버튼을 누른 뒤에는 진행 상태가 자동 갱신되고 완료 시 결과와 실행 정보가 표시된다.
- AE4. **Covers R13.** X credit이 부족한 상태에서 실시간 분석이 실패하면 credit 확인 안내와 다시 시도 행동이 나타나고 Bearer Token이나 provider 응답 본문은 표시되지 않는다.
- AE5. **Covers R7.** 특정 감정에 해당하는 회사가 없으면 해당 영역을 제거하지 않고 결과 없음 상태를 표시해 분석 누락과 빈 결과를 구분한다.

---

## Success Criteria

- 사용자가 `인플루언서 조회 버튼 클릭 → 10명 목록 확인 → Fake 프로필 선택 → 분석 화면 확인 → 회사 결과와 근거 확인` 흐름을 외부 비용 없이 완료할 수 있다.
- 사용자가 Serenity 프로필을 탐색하는 것만으로는 비용이 발생하지 않고, 명시적인 분석 실행 이후 진행과 실패·완료 상태를 이해할 수 있다.
- 네 감정 분류, provenance와 실행 정보를 하나의 화면 흐름에서 검증할 수 있어 Embabel 실험 결과를 CLI 없이도 확인할 수 있다.
- 후속 구현 계획이 로그인, 데이터 출처, 외부 호출 시점, Fake/실제 계정 동작과 화면 완료 조건을 새로 발명하지 않아도 된다.

---

## Scope Boundaries

- 로그인, 회원 관리, 권한, 개인화와 사용자별 저장 기능은 포함하지 않는다.
- 실시간 인기 인플루언서 순위, 검색과 사용자 임의 계정 추가는 포함하지 않는다.
- 실제 X 프로필 이미지를 추가 API로 조회하지 않고 프로젝트가 관리하는 아바타를 사용한다.
- 시세, 포트폴리오, 주문, 투자 추천과 수익 예측 기능은 포함하지 않는다.
- Fake 데이터는 도메인과 화면 상태 검증을 위한 Fixture이며 실제 인물이나 실제 투자 의견으로 표현하지 않는다.
- 첫 버전은 밝은 테마만 지원하고 테마 전환은 포함하지 않는다.

---

## Key Decisions

- 비용 없는 기본 성공 흐름: Fake 인플루언서만으로 전체 SSR 경험을 끝까지 검증할 수 있게 한다.
- 실제 분석의 명시적 실행: Serenity 프로필 진입과 유료 분석 시작을 분리해 우발적인 비용 발생을 막는다.
- 네 가지 감정 영역 유지: 중립과 판단 불가를 합치지 않아 Embabel 구조화 결과의 의미를 보존한다.
- 소셜 피드와 분석 패널의 혼합: 프로필·근거 탐색은 친숙하게, 감정 비교는 명확하게 제공한다.
- 접힌 실험 정보: 일반 분석 결과의 가독성을 유지하면서 Agent 실행과 비용 상한을 검증할 수 있게 한다.

---

## Dependencies / Assumptions

- 기존 인플루언서 추천, 최근 X 분석, 비동기 실행 상태와 결과 조회 capability를 화면에서도 동일하게 사용할 수 있다고 가정한다.
- Fake 인플루언서마다 고정 포스트 10개와 네 감정 상태를 검증할 수 있는 회사 언급 Fixture를 준비한다.
- Serenity 실시간 분석에는 사용자가 준비한 X API credit과 LLM provider 설정이 필요하다.
- 자동 상태 갱신은 서버 렌더링을 기본으로 유지하면서 화면의 필요한 일부 영역만 교체한다.
